# Еженедельный свод SIGIR: самообслуживаемая форма вместо pptx+почты

Перенесено из `maxbot` 04.10.2026 — см. `SESSION_LOG.md` за обоснование решения не
продолжать `client/`/`server/` этого репозитория.

## Контекст

Сейчас: 16 руководителей отделов правят свои мини-шаблоны в `.pptx`, присылают по почте
пользователю, тот вручную собирает в один файл и отдаёт Клоду; Клод конвертирует через
`markitdown` и вручную переносит цифры в HTML-артефакт «Свод недели SIGIR» (ledger-дизайн,
живой URL `https://claude.ai/artifact/8wMDdmHwTafFSkYrRTjj4p`). Узкое место — три ручных
шага (редактирование → почта → сборка), и то, что ассистент не видит первоисточник, только
агрегированный файл.

## Архитектурный разворот 04.10.2026 — ВАЖНО

Первая версия плана (Этап 1 и первая версия Этапа 2) строилась как Claude Artifact с
`db`/`user` capabilities — соавторы редактируют прямо в артефакте под своим Claude-аккаунтом.
**Это оказалось нежизнеспособно**: в России claude.ai открывается только через VPN
(использование которого не рекомендовано), а завести аккаунт Claude нельзя вовсе
из-за санкционных ограничений. Значит ни читать, ни тем более писать через claude.ai
руководители отделов не смогут — нужен свой сервер.

**Новое решение**: лёгкий self-hosted сервер (`server/` в этой же папке) — Node/Express,
без Postgres/Prisma/React (как было в `../client`/`../server` — то и застряло), хранилище —
обычный JSON-файл (не SQLite: `better-sqlite3` требует компиляции node-gyp, ненадёжно для
переноса на прод). Доступ на запись — по длинной случайной ссылке-токену на отдел вместо
аккаунта/логина-пароля: кто обладает ссылкой, тот и пишет. Публичная страница свода не
содержит вообще никаких упоминаний токенов/ссылок на редактирование — это разные страницы.

Код и подробности — `server/README.md`. Эта смена архитектуры НЕ отменяет уже проверенную
модель данных и рендер-движок (block-tree, ~12 типов блоков) — он перенесён as-is из
Claude-артефакта в `server/src/render.ts`, просто теперь это чистые функции на Node, а не
браузерный JS, и хранилище не `db`-capability, а JSON-файл.

## Архитектура (актуальная, self-hosted)

### Хранилище — JSON-файл (`server/src/db.ts`)
- `departments`: `{ [id]: { name, token, editable } }` — токен выдаётся разово (`seed.ts`),
  повторный запуск сида не перевыпускает уже разосланные токены.
- `weeks`: `{ [weekId]: { [deptId]: { status, values, updatedAt } } }` — только для
  редактируемых отделов (сейчас: `peo`, `engineering`); остальные 14 рендерятся прямо из
  статического `DEPARTMENTS` в `render.ts`, как в Этапе 1.

### Маршруты (`server/src/index.ts`)
- `GET /` — публичный свод, читает из файла + мёржит поверх статики для редактируемых
  отделов (`mergeOverlay`). Токены нигде не упоминаются.
- `GET /edit/:token` → `POST /edit/:token` — форма редактирования для отдела, чей токен
  совпал; 404 на неизвестный токен, «форма ещё не готова» на отдел без формы.

### Доступ — ссылка вместо аккаунта
Токен = право на запись в конкретный отдел, выдаётся пользователем лично (через любой
канал — MAX/почту/устно), не через Claude Share. Жёстче, чем было в Claude-варианте
(там была общая запись у всех соавторов + мягкая самопривязка) — здесь каждый токен
технически привязан ровно к одному отделу на уровне сервера.

## Этапы

**Этап 1 — ГОТОВО (04.10.2026, на Claude Artifact).** Рендер из данных, 16 отделов,
~12 типов блоков, проверено живьём. Исторический тестовый артефакт (не используется
дальше): `https://claude.ai/artifact/LD3xCqmtEKQftWbM38WzB9`.

**Этап 2 — ПЕРЕДЕЛАН под self-hosted, ГОТОВ локально (04.10.2026).** `server/` поднимается,
отдаёт публичный свод и форму для ПЭО/Главного инженера, сохранение проверено живьём в
браузере (включая кириллицу). **Не задеплоен на прод** — нужен разовый шаг Вани
(systemd + nginx + поддомен, см. `server/README.md`/`deploy/`), SSH к серверу у ассистента
нет.

**Локальный прогон всех 16 слайдов (04.10.2026, тем же вечером).** По просьбе
пользователя — вместо пилота на 2 отделах сразу собран generic-движок редактирования
(`server/src/fields.ts`): один обход дерева блоков отдела сам находит каждый
редактируемый лист и строит под него поле (textarea «строка=запись», составные —
через `|`). 11 из 16 отделов (все, у кого вообще есть контент) получили форму
редактирования; 5 отделов-заглушек «без отчёта» — как были. `raw`-блоки (графики)
по-прежнему не редактируются. Пользователь тестирует ЗАВТРА локально, заполняя все
слайды сам за руководителей отделов, и даёт обратную связь по технологии — по
итогам, с доработками, разворачиваем у Вани на Debian.

**Этап 3 — полный раскат (после локального прогона).** Авто-переключение недели по
календарю (сейчас `WEEK_ID` зашит константой), возможно — доработка полей по
фидбэку пользователя, приглашение реальных руководителей отделов (разослать
ссылки), остановка сбора pptx по почте, деплой у Вани (см. `server/README.md`).

## Риски (сознательно принятые)

- Токен = простая секретная ссылка, не криптографически заверенная сессия — приемлемо
  для доверенной внутренней команды (тот же дух, что уже принят для ОПРП-канала), но
  ссылку нельзя пересылать публично/в общий чат.
- Графики (Подрядчики, line-chart) остаются ручной правкой — не часть формы, `raw`-блок.
- Нет формального воркфлоу «на проверке/принято» — сохранение сразу публикует.
- Нет авто-переключения недели (Этап 3).
- Требуется один разовый шаг девопса (Вани) для первого деплоя — дальше git push
  обновляет как обычно.
