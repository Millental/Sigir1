# weekly-report-server

Самообслуживаемый свод недели SIGIR — без аккаунтов, без Postgres, без React.
Один Node-процесс, хранилище — обычный JSON-файл. Доступ на запись — по
ссылке-токену (кто обладает ссылкой, тот и пишет; как Typeform/Google Forms
по ссылке, только без стороннего сервиса).

## Почему так

claude.ai в России открывается только через VPN (не рекомендован), создать
аккаунт Claude нельзя из-за санкционных ограничений — значит ни для чтения,
ни тем более для записи полагаться на claude.ai нельзя. Нужен свой сервер.
При этом предыдущая попытка (`../../client`, `../../server` в корне этого
репозитория) переусложнила задачу — Postgres, Prisma, React, полноценная
аутентификация с ролями — и застряла на 2+ месяца. Здесь — минимум: один
процесс, один файл данных, доступ по секретной ссылке вместо логина/пароля.

## Локальный запуск

```bash
npm install
npm run build
npm run seed      # создаёт токены (один раз; повторный запуск их не меняет)
npm start         # либо `npm run dev` для разработки с автоперезапуском
```

Откройте `http://localhost:4100/` — публичный свод. Ссылки на редактирование
`seed` печатает в консоль.

## Структура

- `src/render.ts` — данные по всем 16 отделам (структура+контент недели 39) и
  чистые функции рендера в HTML (тот же визуальный язык, что был на
  claude.ai — `public/style.css` оттуда и перенесён).
- `src/db.ts` — хранилище: один JSON-файл (`data.json` рядом с процессом,
  путь настраивается `DATA_PATH` в `.env`).
- `src/index.ts` — Express: `GET /` (публичный свод, без единой ссылки на
  редактирование — токен не должен быть виден никому, кроме владельца
  раздела), `GET/POST /edit/:token` (форма редактирования для отдела, чей
  токен совпал).
- `src/seed.ts` — разовая генерация токенов. **Повторный запуск не портит уже
  разосланные ссылки** — токен выдаётся только если его ещё нет.

## Что уже редактируется (Этап 2, пилот)

Только 2 отдела — ПЭО и Главный инженер (простейшая структура: два буллет-листа
+ у инженера ещё пара числовых метров). Остальные 14 — статика из `render.ts`,
как раньше; добавить им форму — Этап 3, тот же паттерн (см. `EDITABLE_IDS`,
`defaultValuesFor`, `mergeOverlay` в `render.ts`).

## Деплой на боевой сервер

См. `../deploy/weekly-report.service` (systemd) и `../deploy/nginx.conf.example`.
Коротко: `npm ci && npm run build` на сервере, `.env` из `.env.example`
(обязательно `DATA_PATH` на постоянный путь вне рабочей директории деплоя),
systemd-юнит, nginx проксирует на `127.0.0.1:$PORT`. Никакой базы данных
ставить не нужно — только Node.

**Нужен один разовый шаг от Вани** (у ассистента нет SSH на сервер, только
git push + автодеплой): завести systemd-юнит, поддомен и nginx-конфиг — это
разовая настройка, дальше обновления идут обычным пушем в этот репозиторий.
