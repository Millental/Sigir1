# Инструкция администратора

Описывает все действия, доступные роли «Администратор» в системе еженедельной управленческой
отчётности, по состоянию на Этап 13 (закрытие Вехи 1). Роль «Спикер» видит только заполнение
своих слайдов (см. соответствующий раздел ниже) и не имеет доступа к остальным разделам.

## Вход в систему

Откройте страницу входа, введите логин и пароль. Сессия действует 10 часов, после истечения нужно
войти заново. Забытый пароль администратора восстанавливается только через прямой доступ к серверу
(повторный запуск `npm run seed` или прямая правка БД) — self-service восстановления пароля в
системе нет ни для одной роли; для спикеров пароль сбрасывает администратор (раздел
«Пользователи» ниже).

## Пользователи

Раздел «Пользователи» — список всех учётных записей с ФИО, логином, ролью, отделом и статусом
(активен/деактивирован).

- **Создание** — ФИО, логин, роль (Администратор/Спикер), необязательный отдел. Временный пароль
  показывается один раз сразу после создания — запишите его или передайте пользователю немедленно,
  повторно увидеть его нельзя (только сбросить заново).
- **Редактирование** — ФИО, роль, отдел, статус активности. **Себе самому** администратор может
  поменять только ФИО — роль и статус активности для собственной учётной записи менять запрещено
  (защита от случайной самоблокировки).
- **Сброс пароля** — генерирует новый временный пароль, показывается один раз в интерфейсе, как
  при создании.
- **Деактивация** вместо удаления — деактивированный пользователь не может войти, но его данные
  (слайды, история) сохраняются. Рекомендуемый способ «убрать» сотрудника, если у него уже есть
  слайды/действия в системе.
- **Удаление (безвозвратное)** — доступно только для пользователей без слайдов и уведомлений
  (иначе система откажет с понятным сообщением — учётку с историей нужно деактивировать, а не
  удалять). Единственное действие в системе с диалогом подтверждения — все остальные описанные
  здесь действия срабатывают сразу по клику, без запроса «вы уверены?».
- **Последний активный администратор** защищён системой — понизить его в спикеры, деактивировать
  или удалить нельзя (ни им самим, ни другим администратором), чтобы не потерять доступ к системе
  полностью.

## Отделы

Раздел «Отделы» — простой CRUD (создать/переименовать/удалить). Отдел используется для двух
вещей: группировки пользователей (поле «Отдел» в карточке пользователя) и назначения шаблонов
целому отделу сразу (см. ниже). Удаление отдела **не** удаляет пользователей — у них просто
пропадает привязка к отделу; если это был единственный способ, которым шаблон был кому-то назначен,
шаблон становится видимым всем спикерам (правило «без единого назначения = общий» применяется и
здесь — учитывайте при удалении отделов, у которых есть назначенные шаблоны).

## Шаблоны

Раздел «Шаблоны» — конструктор структуры слайда, которую заполняют спикеры.

Два вида шаблонов:
- **Обычный (поля)** — плоский список текстовых полей с подписью и флагом «обязательное».
- **Блочный (макет)** — используется для более сложных слайдов: сетка блоков одного из макетов
  (квадрант, финансовый график, простая колонка), где каждый блок — один из пяти типов
  (текстовый блок, метрика-плитка, таблица, футер-статистика, изображение графика). Блочный
  шаблон можно собрать вручную конструктором или импортировать из существующего файла `.pptx`
  (кнопка импорта — система распознаёт разметку и типы блоков автоматически, результат можно
  донастроить перед сохранением).

**Обязательные поля/блоки.** Отмеченные как обязательные визуально помечены звёздочкой в форме
спикера. С Этапа 13 система **не позволяет спикеру отправить слайд на проверку**, пока хотя бы
одно обязательное поле/блок не заполнено — кнопка «Отправить на проверку» недоступна, пока форма
не заполнена полностью.

**Изменение уже используемого шаблона.** Если у шаблона уже есть слайды, часть правок делает его
«замороженным» — состав полей/блоков менять нельзя (иначе разъедутся уже собранные ответы), но
можно переименовать, поменять «общий» флаг и назначения. Каждое изменение состава полей/блоков
создаёт новую версию шаблона — историю версий видно в карточке шаблона.

**Назначение шаблона.** Флаг «Общий» делает шаблон видимым всем спикерам. Альтернатива —
назначить шаблон конкретным спикерам и/или конкретным отделам чекбоксами (можно сочетать оба
способа одновременно). Если у шаблона нет ни флага «общий», ни единого назначения — он всё равно
считается видимым всем (чтобы старые шаблоны без миграции данных не «пропали» из вида спикеров).

## Недельные циклы

Раздел «Недельные циклы» — список циклов с датами начала/окончания, необязательным дедлайном и
статусом (Сбор → Собран → Архив).

- **Создание/редактирование** — название недели, даты, дедлайн. Статус вручную не меняется —
  только через отдельные действия ниже.
- **Напомнить спикерам** (кнопка доступна, пока цикл в статусе «Сбор») — открывает панель с
  чекбоксами активных спикеров (по умолчанию отмечены все) и необязательным полем текста. Отправляет
  каждому выбранному спикеру уведомление с напоминанием подготовить слайд к дедлайну. Это ручное
  действие администратора — отдельно от автоматического уведомления «дедлайн приближается»,
  которое система показывает спикеру сама за 24 часа до дедлайна, если у него ещё нет отправленного
  слайда.
- **В архив** (доступно после сборки презентации, статус «Собран») — переводит цикл в статус
  «Архив». Слайды и презентация физически сохраняются, просто цикл закрывается для дальнейших
  изменений.
- **Из архива** — обратное действие, возвращает заархивированный цикл обратно в статус «Собран»
  (презентация остаётся как была). Дальше цикл снова можно, при необходимости, разобрать
  (см. ниже) — прямого возврата из архива сразу в «Сбор» нет.
- **Разобрать** (доступно в статусе «Собран») — удаляет презентацию как объект, слайды
  возвращаются в статус «Отправлен» и их можно заново включить в презентацию. Используйте, если
  состав презентации нужно пересобрать с нуля.

## Проверка слайдов (раздел «Проверка»)

Список слайдов спикеров, отправленных на проверку, по выбранному циклу. Для каждого — «Принять»
(оставляет статус «Отправлен», слайд становится доступен для включения в презентацию; это
осознанно не отдельный статус «Принято» — действие фиксируется только в журнале аудита) или
«Вернуть на доработку» с обязательным комментарием (статус меняется на «На доработке», спикер
видит комментарий и может отредактировать поля заново).

## Сборка презентации (раздел «Презентация»)

Для выбранного цикла — два списка: уже собранные слоты презентации (с возможностью менять
порядок стрелками и удалять слот) и кандидаты — отправленные на проверку слайды спикеров, ещё не
включённые. Добавление слайда переводит его в статус «В презентации» (дальше спикер его уже не
редактирует). Можно также добавить текстовую заглушку вместо слайда, если кто-то не сдал —
это ручное действие администратора, а не автоматическая подстановка. Первое добавление
слайда/заглушки в пустой цикл переводит его статус в «Собран».

## Экспорт в PDF

На странице презентации — кнопка экспорта всей презентации целиком и отдельная кнопка на каждом
слоте для экспорта одного слайда. Формат — альбомная A4, с титульной страницей для полной
презентации. Файл скачивается сразу, на сервере не сохраняется.

## Журнал аудита (раздел «Аудит»)

Полный список действий всех пользователей — кто, что, когда, над каким объектом. Фильтры по
периоду, типу действия, типу объекта и пользователю, подгрузка постранично («Показать ещё»).
Полезно для расследования инцидентов и для проверки, что конкретное действие (например,
разархивирование цикла или рассылка напоминания) действительно было выполнено и кем.

## История значений и версий

- На форме заполнения слайда и на странице проверки — панель истории: кто и когда менял каждое
  поле/блок, старое и новое значение.
- В карточке шаблона — история версий: снимок состава полей/блоков на момент каждого изменения.

## Уведомления

Колокольчик в шапке показывает непрочитанные уведомления: автоматические (у администратора — «все
слайды цикла отправлены на проверку»; у спикера — «дедлайн приближается», «слайд возвращён на
доработку», плюс адресованные лично ему напоминания администратора) и постоянные записи о
жизненном цикле презентации (собрана/архивирована/разобрана). Клик по уведомлению ведёт на
соответствующий экран; крестик скрывает уведомление без прочтения.

## Что видит спикер (для справки)

Спикер видит только раздел «Мои слайды»: выбор доступного ему цикла и шаблона (общие + назначенные
лично ему/его отделу), заполнение полей или блоков с живым предпросмотром, сохранение черновика,
отправка на проверку (недоступна, пока не заполнены все обязательные поля/блоки), просмотр
комментария при возврате на доработку и собственной истории изменений.
